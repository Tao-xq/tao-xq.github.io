# Daily Notes 个人写作台

在 Windows 上双击仓库里的 **Daily Notes 写作台.cmd**。它会启动本机写作服务，并在浏览器打开 `http://127.0.0.1:4186/`。服务已经运行时会直接打开，不重复启动。

需要 Node.js 24、Git 和项目依赖。电脑已通过 Git 登录 GitHub 时，发布沿用现有凭据，不需要把访问令牌填到网页里。命令行也可以用 `npm run daily` 启动，再打开上述地址。

## 写作与保存

左侧可以新建、查找和切换草稿。正文支持标题、字号、加粗、斜体、下划线、删除线、颜色、列表、引用、代码块、链接、分隔线，以及撤销和重做。

照片可以多选上传、粘贴或拖入正文。点击照片可设置宽度、对齐、替代文字和照片说明，也能移动或移除。文章封面可以从电脑或正文照片中选择，再裁剪为 A4 竖版。

文字会自动保存在电脑上。点击「保存草稿」还会保留一个历史版本；可以在「历史版本」中恢复。回收站只归档本机草稿，不删除已发布文章。

中文、英文和日文按钮用于编写原文及校对译文，发布时一起保存。没有填写的译文不会公开。读者仍需点击翻译才会看到译文。

「导出完整备份」下载 `.restnotes.json`，包含正文、排版和全部配图，可以在另一份写作台中导入。「导出阅读版 HTML」则下载可独立阅读的图文文件。旧版图文草稿通过「保存一份」导出的 HTML 也可以导入。

本机草稿、图片、历史版本和发布记录位于 `.local/daily-studio/`，该目录被 Git 忽略，不随代码或网站发布。它不会依赖临时照片目录。首次启动时，如果上一级的 `drafts/drinks-2025/draft.json` 仍在，会把那份初稿及照片导入为未发布草稿；已有新草稿后不会覆盖。

## 发布到个人网站

先预览并检查文章，再点击「发布到 GitHub」。写作台会列出标题、图片数量和将提交的文件。点击第二步「确认发布到 GitHub」后，才会进行同步、构建检查、提交和推送。

发布只写入当前文章的 `content/daily/daily-….json` 和 `web/assets/daily/文章ID/` 配图目录。文章保留富文本格式。已有 Markdown 随笔继续支持原有的 GitHub 维护方式。

仓库必须处于 `main`，且没有未处理的改动。写作台会同步远端；出现分叉、文件冲突、文章被别人更新或构建失败时会停止，保留草稿。如果提交成功但网络推送失败，可以在发布窗口重试推送。

推送完成后，GitHub Actions 还需要构建与部署网站。发布窗口提供进度和文章链接；构建失败时到 GitHub Actions 查看记录。

在写作台左下角点击「关闭写作台」可以停止本机服务。下次使用时再次双击入口即可。

## 本机访问保护

服务只监听 `127.0.0.1`，限制 Host 与 Origin，写入还要求同源会话及 CSRF 校验。网页不能直接执行 Git 命令或指定任意文件路径。所有公开正文在构建时都会净化；图片上传检查实际文件类型和尺寸。GitHub 的账号凭据由本机 Git 管理，不发送给前端。
